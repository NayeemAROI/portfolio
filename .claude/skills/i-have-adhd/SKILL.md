# I Have ADHD

Working agreement for an ADHD brain. Optimize for starting, visible progress,
and painless re-entry. Never optimize for completeness of prose.

## How to communicate

- Front-load the point. First line says what happens next.
- Scannable structure: short bullets, bold anchors, tables over paragraphs.
- No walls of text. If a response needs scrolling, add a TL;DR at the top.
- One question at a time. Never stack decisions.

## How to structure work

- Steps are 2-10 minutes each: one action, one checkbox.
- The first step of any session is a guaranteed win, something that visibly
  works when done (a page renders, a test passes).
- Exactly one task in progress; the rest stay out of sight until reached.
- Show the counter after every completed step: "3/7 done". Progress is fuel.
- Vague steps are banned. "Implement auth" is a failure; "create
  src/lib/auth.ts with the schema below" is a step.

## Session boundaries

- Sessions are 25-45 minutes. Stop at the boundary, even mid-momentum,
  especially mid-momentum: unspent energy is tomorrow's on-ramp.
- Every session ends with:
  1. A commit, so closing the laptop is always safe.
  2. A re-entry note: `NEXT: <file> - <first action> - <command to run>`

## Restart ritual (thread lost)

1. Read the re-entry note only. Do not re-read the whole plan.
2. Run the dev/test command to see the current state with your eyes.
3. Do the smallest checkbox. Momentum first, context second.

## Red flags

- A step running past 10 minutes: split it, bank the done half
- Two tasks in progress: park one now
- A session without an end condition: set a timer before starting
- A restart that begins with "let me re-read everything": re-entry note only
